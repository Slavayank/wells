# Принятые решения и их основания
1. **As-of = 2026-08-13** (дата выгрузки) + roll-forward от снимка на 1-е. Для 1 августа: `--as-of 2026-08-01`. Один параметр для всех таблиц.
2. **Возвраты: net = sold − returned**, возврат возвращается на склад (данные: roll-forward точнее на 5 п.п.).
3. **Покрытие по категориям** (60/90 дней, ASSUMPTION) + `procure sensitivity` (30/60/90/120, service level, масштаб спроса, политика по PO).
4. **Стек: Python-расчётный движок + CLI + статичный HTML-дашборд** (без сервера, открывается двойным кликом, пересоздаётся при каждом прогоне). Streamlit не установлен в среде сборки и не нужен для расчёта; тонкую обёртку над `runs/LATEST` можно добавить позже.
5. **Цензурирование спроса выключено по умолчанию** — backtest показал ухудшение (см. FORMULAS §1).
6. **Нулевые остатки не выгружаются** — отсутствие строки = 0 со статусом (а не «нельзя посчитать»).
7. **Контейнеры по весу не считаются как гарантия**: `weight_kg` заполнен у 7 из 791 SKU. Показываем штуки; вес — только по SKU, где он есть.
8. **Периодичность**: данные месячные → ежедневный прогон пересчитывает остатки/PO/сроки, но не прогноз. CLI пропускает пересчёт, если хэши входов, as-of и конфига не изменились (`--force` отключает).
